# Приёмка Авроры для фасада 2.0.0

24 ноября 2026 на эмуляторе Aurora 5.2.1.200 aarch64 установлен подписанный
release RPM. Сборка использовала Flutter Аврора 3.41.4, Tracer Native 0.1.15,
Sentry Dart 9.30.1 и код адаптера из `31e31b0`. В 20:17 МСК тестовый
C/C++ проект принял серию `aurora-release-matrix` с версией 2.0.0.
Для повторения соберите [fixture](../tool/aurora/acceptance/README.md)
и выполните `run.py facade-matrix` с теми же SSH-параметрами, что и для
`facade-dart`. На живом проекте каждая новая серия увеличивает счётчики.

| Сценарий | Что подтвердилось |
| --- | --- |
| Обработанная ошибка | В карточке ERROR видны `StateError`, сообщение и `manualFailure` в `live.dart:7`. |
| Ошибка Flutter | Вызов `FlutterError.reportError` открыл отдельную группу, в отчёте видны `FlutterError` и `frameworkFailure` в `live.dart:10`. Прежний обработчик вызван один раз. |
| Необработанная async-ошибка | Исключение из microtask дошло до PlatformDispatcher. В Tracer видны `ArgumentError` и `asyncFailure` в `live.dart:13`. Процесс продолжил работу. |
| Группировка | Явный ключ `aurora-matrix-same` объединил три события от двух пользователей. `aurora-matrix-different` дал одно событие от одного пользователя. |
| Фильтрация и дубли | По четырём группам в кабинете получилось 3 + 1 + 1 + 1 событий. Каждая ручная ошибка дважды прошла через публичный API с теми же объектами. Ошибка, которую отбросил `beforeSend`, и вызов после отзыва отчётов не создали. |
| Контекст и смена аккаунта | В карточках A видны ID, ключ `matrix_account` и русский breadcrumb. Поиск по ID B показывает одну ручную ошибку в 20:17:44 после очистки. При открытии группы UI выбирал первое событие A. Содержимое отдельного envelope B, включая отсутствие данных A, проверено в фазе `facade-lifecycle`. |
| Падение runner | В подписанном RPM без отладчика проверены SIGABRT с ключом и русским логом, SIGTRAP с исходной строкой, восстановление после потери сети и очистка при отзыве. [Символы runner](aurora-symbols.md) и [нативные фазы](../tool/aurora/acceptance/README.md). |

В карточках Dart отображались платформа Aurora, версия 2.0.0 и тип ERROR.
В контексте ручного отчёта проверено поле `fatal: false`. Число в скобках
кабинет вывел как `200000000000000` при отправленном `dist: 204`. В виджете ОС
для Dart было «Данных нет». Нативный отчёт показывает Aurora 5.2.1.200 и свой
номер сборки. Заголовок «Stacktrace not available» может соседствовать с
читаемым стеком внутри карточки. Показатель crash-free в проекте объединяет
данные разных запусков. Для этой интеграции не подтверждён отдельный знаменатель
активных сессий, поэтому значение crash-free и обнаружение ANR не заявляются.

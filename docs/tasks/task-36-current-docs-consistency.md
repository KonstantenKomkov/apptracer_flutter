# П. 36. Смысловая согласованность актуальной документации

**Статус:** открыта. **Приоритет:** P2. **Сложность:** S.

Связанные документы: [карта документации](../README.md),
[завершённая навигация №30](task-30-documentation-navigation.md),
[общий план](development_v1.md).

## Контекст

Link checker подтверждает существование ссылок, но не их актуальность. В текущих
инструкциях и Dartdoc остались утверждения, что desktop не поддерживается, DSN не
выдаётся, а стабильный desktop adapter экспериментален. Это противоречит
`docs/platform-matrix.md` и опубликованным пакетам.

## Цель

Устранить известные противоречия в текущих руководствах, не переписывая
исторические acceptance-протоколы задним числом.

## Сделать

1. Исправить комментарий в Makefile, Dartdoc `TracerOptions.dsn`, library docs
   HTTP transport и текст предупреждения `UnsupportedTracerPlatform`. Для
   поддерживаемых desktop-конфигураций указать optional `apptracer_flutter_desktop`,
   официальный Sentry SDK и DSN. Для Web сохранить инструкцию с app token,
   для Авроры — фактический статус из [матрицы](../platform-matrix.md).
2. Проверить соседние RU/EN quick start, package docs и platform matrix на те же
   устаревшие утверждения и статусы старых версий.
3. Ссылаться на platform matrix для изменяемых версий/поддержки, сохраняя нужные
   минимальные примеры и внешние anchors.
4. Обновить comments/Dartdoc вместе с затронутым кодом и changelog только там,
   где это требуется пакетной публикации.
5. Не менять исторические `status.md`, dated acceptance/audit и release evidence,
   кроме явной навигационной пометки при реальной необходимости.

## Критерии приёмки

- Текущие инструкции не направляют desktop-пользователя в устаревший HTTP transport
  и не называют DSN недоступным.
- RU/EN документы и Dartdoc описывают одинаковое фактическое поведение.
- Исторические свидетельства сохранены в исходном смысле и отделены от current docs.
- Все локальные Markdown links/anchors проходят проверку.

## Проверки

- Documentation unit/link checker для всех tracked Markdown.
- Analyze затронутых пакетов, полный `make check` при изменении Dart comments/code.
- Сверить заявленные версии с [записями публикаций](../publishing.md),
  ограничения — с матрицей, отдельно отметить версии из рабочего pubspec,
  которые ещё не опубликованы.

## Не входит

- Массовая реорганизация документации.
- Документирование незавершённых №31–35/37 как выпущенных возможностей.

# П. 31. Воспроизводимые GitHub Actions по commit SHA

**Статус:** открыта. **Приоритет:** P0. **Сложность:** S.

Связанный общий план: [development_v1.md](development_v1.md).

## Контекст

Основной `.github/workflows/ci.yml` закрепляет actions по полному commit SHA, но
платформенные и служебные workflow используют изменяемые теги `@v2`, `@v5`,
`@v7` и другие. `flutter-baseline-update.yml` при этом имеет `contents: write`.

## Цель

Исключить незаметную смену исполняемого action без изменения репозитория и
сделать правило воспроизводимости проверяемым.

## Сделать

1. Заменить теги всех сторонних и GitHub-owned actions на полные проверенные
   commit SHA, сохранив версию в комментарии. Версии не обновлять без необходимости.
2. Сохранить текущие permissions, triggers, reusable workflow inputs и поведение jobs.
3. Добавить лёгкую проверку, которая отклоняет незакреплённые `uses:` для внешних
   actions и не ломает локальные reusable workflows (`uses: ./...`).
4. Подключить проверку к актуальному CI/docs-independent пути и описать её в
   `docs/contributing.md`.
5. Убедиться, что Dependabot продолжает распознавать и обновлять закреплённые actions.

## Критерии приёмки

- Во всех `.github/workflows/*.yml` внешние `uses:` закреплены полным SHA с
  человекочитаемой версией рядом.
- Проверка падает на теге/branch reference и проходит на полном SHA и local `uses:`.
- Diff workflow меняет только ссылки и необходимую автоматическую проверку/документацию.
- YAML и автоматические тесты проверки проходят; CI изменённой ветки зелёный.

## Проверки

- Unit-тест нового скрипта, включая SHA, тег, branch, local reusable workflow и
  многострочный `uses:`.
- Существующие `tool/tests` и профильные workflow для изменённых файлов.
- `git diff --check`, `git status --short`.

## Не входит

- Обновление версий actions ради последнего номера.
- Изменение permissions, secrets, triggers или состава acceptance jobs.

## External dependency resolution

The consumer lives in a temporary directory with spaces outside the repository.
It is generated by `flutter create` and imports only the public facade in its
application source; automatic desktop plugin registration is exercised.

| Dependency | Source | Resolved version |
|---|---|---|
| apptracer_flutter_desktop | isolated path export | 0.1.0-dev.1 |
| apptracer_flutter | hosted pub.dev | 0.2.1 |
| apptracer_flutter_platform_interface | hosted pub.dev | 0.2.0 |
| apptracer_flutter_android | hosted pub.dev | 0.2.1 |
| apptracer_flutter_ios | hosted pub.dev | 0.2.0 |
| apptracer_flutter_web | hosted pub.dev | 0.2.0 |
| apptracer_flutter_http | hosted pub.dev | 0.2.0 |

No consumer overrides or workspace are used. The staged dry-run excludes
development overrides and local environment files. Exact SDK pinning is retained
because the integration uses version-specific APIs. The repository remains
`publish_to: none`; no desktop version has been published by this check.

Reproduce with:

```sh
python3 tool/check_macos_consumer.py --output build/macos-consumer
```

Local artifacts are under `build/macos-acceptance/` and
`build/macos-consumer-final/`: logs, receiver reports, export inventory and
consumer lockfile. CI retains the equivalent reports plus the release product
ZIP (preserving permissions/symlinks), dSYMs, binary hashes/UUIDs and toolchain
metadata for 14 days.

## Hosted runner

[`macos.yml`](../.github/workflows/macos.yml) selects `macos-15` arm64, pins
Flutter 3.47.4 and runs on matching main/PR changes, `codex/macos-*` branch
pushes, or manual dispatch. Runner labels are documented by
[GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
It runs the real release app against loopback, not only mock-channel tests.
Hosted results are recorded after the workflow finishes; local success alone
does not count as a hosted pass.

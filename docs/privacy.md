# Какие данные уходят с устройства

Пакет рассчитан на приложения, которым приходится отвечать за каждое
передаваемое поле, поэтому умолчания намеренно скудные: **на Android и iOS сам
пакет не добавляет никаких персональных данных.** Всё, что он там отправляет, —
это либо свойство самой ошибки, либо то, что приложение передало ему явно.

Нативный SDK вендора собирает собственные метаданные независимо от того,
установлен ли этот пакет. Web и прежний ручной HTTP-транспорт заводят
идентификатор устройства и шлют контекст клиента. Новый опциональный
`apptracer_flutter_desktop` использует официальный Sentry SDK; его дополнительные
данные и ограничения фильтрации описаны отдельно ниже.

## Что отправляет пакет

| Поле | Содержимое | Когда | Чем отключается |
|---|---|---|---|
| Тип исключения | тип Dart в рантайме, например `FormatException` | каждое событие | — |
| Сообщение | `error.toString()` без продублированного префикса типа | каждое событие | `beforeSend` |
| Стектрейс | разобранные кадры Dart: член, URI файла, строка, колонка | каждое событие | `beforeSend` |
| Дословный стектрейс | тот же трейс неизменённым текстом, в буфере лога | каждое событие | `attachRawStackTraceAsLog: false` |
| Уровень, признак фатальности, отметка времени | — | каждое событие | — |
| `issueKey` | передан вызывающим кодом или синтезирован на iOS из типа и верхнего кадра | каждое событие | — |
| Breadcrumbs | свободный текст, который пишет приложение | в событиях, плюс дублируются в нативный лог по мере появления | `maxBreadcrumbs: 0`, `beforeBreadcrumb` |
| Кастомные ключи | пары ключ-значение, которые пишет приложение | каждое событие | не задавать их |
| `dart.exception_type`, `dart.needs_symbolication`, `dart.build_id` | диагностика для символизации | каждое событие | — |
| Идентификатор пользователя | то, что приложение передало в `Tracer.setUserId` | только после этого вызова | не вызывать его |

Ничто в этом списке не заполняется автоматически из устройства, установки или
пользователя. Это общая часть, она одинакова на всех платформах; что транспорт
на чистом Dart добавляет к ней, перечислено
[ниже](#транспорт-на-чистом-dart). Сообщение или путь к файлу, разумеется, могут содержать
персональные данные, если приложение их туда положило, — `beforeSend`
существует ровно для этого случая:

```dart
TracerOptions(
  beforeSend: (event) => event.message.contains('@')
      ? event.copyWith(message: '<скрыто>')
      : event,
)
```

`beforeSend` выполняется до того, как что-либо передаётся платформе. Хук,
который бросил исключение, логируется и игнорируется, а исходное событие всё
равно отправляется: терять ошибки из-за бага в правиле очистки — отказ хуже.

## Замечание про отладочное логирование

При `TracerOptions.debug` iOS SDK пишет собственный лог в консоль, и в этом логе
есть URL загрузки **вместе с query-параметром `crashToken`**. Наблюдалось
26.08.2026. Держите консольный вывод debug-сборок подальше от общих логов и
записей экрана — либо считайте токен раскрытым. Собственная диагностика пакета
печатает не более первых шести символов токена.

## Что нативный Android SDK отправляет сам

Собирается самим `ru.ok.tracer`, задокументировано вендором и **не управляется
из Dart**:

`date`, `board` (`Build.BOARD`), `brand`, `cpuABI` (`Build.SUPPORTED_ABIS`),
`device`, `manufacturer`, `model`, `osVersionSdkInt`, `osVersionRelease`,
`cpuCount`, `operatorName` (мобильный оператор, если доступен), `installer`
(пакет-установщик).

Начиная с SDK 1.4.0 каждый краш дополнительно несёт **свободное место в
хранилище устройства** — вендор добавил это, потому что заполненное хранилище
оказалось частой причиной сбоев.

Замечено вживую 26.08.2026 на SDK 1.4.0, во вкладке «Данные» реального события:
отчёт несёт ещё и **свободную оперативную память** на момент краша. Среди
собираемых полей вендор её не перечисляет, так что относитесь к списку выше как
к нижней границе, а не как к исчерпывающему перечню.

Вместе это образует довольно различимый отпечаток устройства. Метрике crash-free
дополнительно нужна идентичность на уровне установки: вендор пишет, что один и
тот же пользователь на двух устройствах — или после переустановки — считается
двумя единицами, а значит идентификатор, привязанный к установке, существует.

Чтобы не было ничего из этого, не добавляйте Android SDK Tracer: пакет
деградирует до «на Android не отправляется ничего», а не падает.

## Что нативный iOS SDK отправляет сам

SDK OKTracer собирает системную информацию через
`TracerSystemInfoProviderProtocol`. Приложение, которому нужно это ограничить,
может подставить собственную реализацию — но только из нативного кода, потому
что этот пакет такой хук наружу не отдаёт.

## Транспорт на чистом Dart

Этот раздел относится к Web и прежнему ручному HTTP-транспорту. Он не описывает
новый адаптер `apptracer_flutter_desktop`.

Здесь пакет добавляет от себя. Формат тела снят с живого запроса JS-SDK
вендора (см. [web-protocol.md](web-protocol.md)), а тот всегда кладёт в
`uploadBean` идентификатор устройства и контекст клиента — пакет повторяет его
поле в поле. Сверх таблицы первого раздела уходит:

| Поле | На web | На десктопе и Авроре |
|---|---|---|
| `deviceId` | UUID в `localStorage`, ключ `apptracer_flutter.deviceId` | UUID, новый на каждый запуск процесса, если приложение не передало свой в `PlatformClientFacts(deviceId: …)` |
| `sessionUuid` | новый UUID на каждую загрузку страницы | новый UUID на каждый запуск |
| `host` | `window.location.host` | имя ОС из `Platform.operatingSystem` |
| `screenWidth`, `screenHeight`, `screenOrientationAngle` | реальные размеры и угол поворота экрана | нули |
| `documentVisibilityState` | `document.visibilityState` | всегда `visible` |
| `versionName`, `versionCode` | `release` и `dist`; на web подставляются из `version.json` сборки | `release` и `dist` |

**`deviceId` на web — это идентификатор установки.** Он один и тот же у всех
событий браузера, пока пользователь не очистит данные сайта, и отключить его
нечем. Обойдётся ли приём без него, проверить нельзя: сервер отвечает
`200 {"success":true}` даже на мусорное тело, так что молчаливая потеря событий
была бы неотличима от успеха. В приватном окне и там, где хранилище запрещено,
он не сохраняется и живёт столько же, сколько вкладка. На десктопе и
Авроре он по умолчанию не переживает перезапуск — Tracer будет считать каждый
запуск новым устройством, — а стабильную идентичность приложение задаёт само,
передав `deviceId` в `PlatformClientFacts`.

Чего транспорт по-прежнему не делает: не собирает модель устройства, ОС,
оператора связи и свободную память, как нативный SDK, и не заводит
идентификатор пользователя — `userId` уходит только после `Tracer.setUserId`.

Учтите, что любой HTTP-запрос раскрывает принимающему серверу IP-адрес клиента.
Это свойство сети, а не этого пакета.

## Опциональный desktop SDK

На Ubuntu 22.04 x64 используется sentry-native 0.16.6, backend `native`.
После согласия адаптер добавляет дистрибутив/версию ядра, архитектуру и DMI
model/vendor; hostname, serial и machine-id не читаются. Native SDK добавляет
собственные сведения о процессе/модулях и minidump. Dart `beforeSend` не фильтрует
нативное падение. Sessions/crash-free, performance и replay отключены.

Очередь находится в `$XDG_DATA_HOME/apptracer_desktop/<executable-name>/v1`
(fallback `$HOME/.local/share`). Имя executable должно быть постоянным и
уникальным. Stop сохраняет отзыв, отменяет собственные отправки и требует
нового процесса после native init; clear удаляет очередь, scope и идентичность.
Отозванные отчёты не восстанавливаются даже при preserve=true. SDK повторяет
сетевые обрывы, но отбрасывает HTTP 5xx. Доставленные серверу данные не удаляются.

Карты символов Ubuntu содержат имена функций и пути файлов; компактная Dart-карта
ослабляет обфускацию. Полный DWARF и текст исходников не нужны в bundle.
В примере карту можно исключить через `TRACER_BUNDLE_DART_SYMBOLS=0`;
без неё нет автоматического восстановления Dart-строк на клиенте.
Проверенные границы очистки и системные требования — в
[Ubuntu-протоколе](linux-preparation.md).

На macOS `apptracer_flutter_desktop` использует sentry_flutter 9.30.1 и Cocoa
8.58.4. В проверенных событиях есть сведения об ОС/ядре, архитектуре, модели
и памяти устройства, версии/идентификаторе приложения, locale, времени старта,
trace IDs и native image UUID. Dart-события также могут нести Flutter runtime,
тему, accessibility и культуру. Это не исчерпывающий список автоматически
собираемых SDK данных; [проверенный протокол](macos-lifecycle-acceptance.md).

Адаптер отключает автоматические sessions, performance/profiling, replay,
screenshots, view hierarchy, logs/metrics и автоматические breadcrumbs.
Явно заданные userId, custom keys и breadcrumbs передаются в native Scope.
Native crash не проходит через Dart `beforeSend`: фильтрация Dart-события
не удаляет уже записанные native значения. Исходный Dart-стек сохраняется
в `contexts.apptracer.dart_stack_trace` и может содержать пути/текст приложения.

На macOS disabled/deferred bootstrap не запускает SDK. Успешный stop запрещает
новые native-запросы и ждёт отмены сетевой сессии; stop/clear после попытки init
требует нового процесса для повторного старта. Clear удаляет только принадлежащие
адаптеру данные и оставляет маркер отзыва, запрещающий replay. Прежние очереди
другого транспорта и системные crash-логи macOS не удаляются. Уже доставленные
серверу отчёты локальная очистка также не удаляет.

Windows cleanup/отзыв сети ещё не приняты; эти результаты macOS нельзя
переносить на Windows. Порядок перехода и границы очистки:
[desktop-migration.md](desktop-migration.md).

## Согласие не опционально

Лицензионное соглашение Tracer возлагает это на вас, а не на вендора и не на
этот пакет. Два пункта редакции от 29.05.2025:

* **1.2** — вы являетесь оператором персональных данных своих конечных
  пользователей и *поручаете* их обработку VK как обработчику в целях
  соглашения.
* **1.3** — вы **обязуетесь получить согласия конечных пользователей, требуемые
  применимым правом**, для такой обработки.

Согласие проверяет приложение. `isCollectionEnabled=false` запрещает Dart-события,
но Android providers запускаются до Dart. Для запрета раннего нативного старта
нужно удалить оба provider из manifest и использовать отложенный bootstrap.

Новый контракт `startCollection`, `getCollectionState` и `stopAndClearCollection`
описан в [native-collection-consent.md](native-collection-consent.md). Адаптеры
проверяются с Android SDK 1.4.0 и OKTracer 1.5.2; они очищают известные хранилища
SDK и запрещают новые отправки. После активной нативной сессии требуется новый
процесс для следующего разрешённого старта (`restartRequired`). Остановка сразу
запрещает новые Dart-события и очищает Dart-буферы. Не считать
`error`/`unsupported` успешным отзывом транспорта. Проверенные сценарии и границы
версий приведены в журнале по ссылке выше.

Web/HTTP не хранит очередь отчётов на диске и не повторяет неудачные запросы.
Остановка очищает логи, custom keys и user ID, закрывает принадлежащий транспорту
HTTP-клиент и возвращает `disabled`. Повторный явный старт создаёт новый клиент;
данные, переданные при выключенном сборе, отбрасываются. Переданный извне клиент
остаётся собственностью приложения и не закрывается транспортом.

Отчёты, доставленные серверу, локальная очистка не удаляет. Для Web/HTTP-транспортов
отмена уже начатых сетевых запросов не подтверждена; она отличается от запрета новых отправок.

## Где хранятся данные и сколько

Tracer заявляет, что данные хранятся в России, а события держатся последние 90
дней. И то и другое — свойства сервиса, а не этого пакета; проверяйте их по
своему договору с вендором, а не по этому файлу.

## Где заканчиваются обязательства вендора

Стоит прочитать до того, как решать, сколько данных отправлять. По соглашению
Библиотека предоставляется **«как есть» (as is)**, пункт 2.1: Лицензиар не
гарантирует пригодности для конкретной цели и не обещает определённых
результатов. Пункт 6.2.2 позволяет Лицензиару приостановить или прекратить
доступ Лицензиата в любой момент без объяснений и уведомления, а заключительный
пункт 4.1 разрешает менять само соглашение без предварительного уведомления.

Ничего необычного для бесплатного сервиса в этом нет, и к этому пакету оно
отношения не имеет. Но означает вот что: диагностика, потерять которую вы не
можете себе позволить, не должна жить только в Tracer.


### Отзыв на iOS, OKTracer 1.5.2

Плагин сохраняет факт отзыва до остановки SDK, отсоединяет остановленный сервис, удаляет
ожидающие отчёты и заменяет каталоги SDK пустыми файлами. Оставшийся обработчик
нативного падения не может сохранить новый отчёт по этим путям. Автоматический
старт после перезапуска остаётся выключенным; новое согласие требует явного
старта в deferred-режиме и предварительной очистки. После активной сессии
остановка возвращает `restartRequired`, при ошибке очистки — `native_cleanup_failed`.

Это адаптер строго для OKTracer 1.5.2, а не публичный API удаления SDK.
Уже начатый запрос может завершиться; серверные данные не удаляются.
Проверки и ограничения: [журнал](native-collection-consent.md).

Один остановленный объект SDK удерживается до завершения процесса: немедленное
освобождение при старте вызывает внутреннюю ошибку `unowned` в SDK. Объект не
переиспользуется; очистка всей его памяти до выхода процесса не обещается.

## Android tombstones (SDK 1.5.2)

Экспериментальный сбор системных tombstones на Android 12+ выключен по умолчанию.
Он включается флагом `ru.apptracer.flutter.experimentalTombstoneEnabled` в манифесте
или через `CrashReportConfiguration.Builder.setExperimentalTombstoneEnabled(true)`.
Это нативные отчёты SDK: Dart `beforeSend` их не фильтрует.

При отложенном запуске флаг не заменяет явный `startCollection`. Очистка удаляет
сохранённое состояние предыдущего запуска SDK, необходимое для формирования
такого отчёта; системная история `ApplicationExitInfo` остаётся у Android.
См. [аудит 1.5.2](android-sdk-1.5.2.md) и границы выполненных проверок.
